# Gradient Boosting: what was done, what each file holds

This is the reference for writing the Gradient Boosting section of the
report. Every number below comes from the files listed here, and every file
can be regenerated by running the six scripts in order.

It follows the same layout as `RANDOM_FOREST.md` and `SVM.md`. The tasks, the
data split, 5-fold cross-validation, the standard deviation across folds and
the metrics are explained in sections 1 and 2 of `RANDOM_FOREST.md`. ROC-AUC,
hyperparameters, random search, grid search and permutation importance are
explained in section 2 of `SVM.md`.

All results are **without the compile date** (`hdr_TimeDateStamp`), on the
same **299 features** as the other two models. This model was never run with
the compile date, and it was **scored on the test set once**.

## 1. The two tasks

| Task name | Question | Training set | Test set |
|---|---|---|---|
| `binary` | Is this file malware or benign? | 18,768 files (1,501 benign, 17,267 malware) | 4,693 files (375 benign, 4,318 malware) |
| `family` | Which of the 6 malware types is it? | 17,267 malware files | 4,318 malware files |

One model is trained per task.

## 2. Ideas needed to read the results

**Gradient boosting.** An ensemble of decision trees built one after another.
The first tree makes a rough prediction. Each later tree is trained to
correct the errors that the trees before it still make, and the final
prediction is the sum of all the trees' outputs.

**Boosting compared with bagging.** The Random Forest uses bagging: its trees
are trained independently on random samples and then vote. Gradient boosting
trains its trees in sequence, each depending on the previous ones. Boosting
usually reaches a higher score but has more hyperparameters that matter, and
it over-fits if run for too many iterations at too high a learning rate.

**Histogram-based gradient boosting.** The implementation used is
scikit-learn's `HistGradientBoostingClassifier`. Before training, it groups
each feature's values into at most 255 bins, so that a tree only has to
consider 255 possible split points per feature instead of every distinct
value. This is the same technique used by LightGBM and by XGBoost's `hist`
method, and it is what makes training fast.

**No preprocessing.** As with the Random Forest, trees only ask whether a
value is above or below a threshold, so no log transform or standardisation
is needed.

**Hyperparameters tuned.**

| Hyperparameter | Meaning |
|---|---|
| `learning_rate` | How much of each new tree's correction is applied. A small value makes each step cautious, so more iterations are needed, but the result is usually more stable. |
| `max_iter` | The number of boosting iterations. For `binary`, one tree is built per iteration. For `family`, one tree per class per iteration (6 trees). |
| `max_leaf_nodes` | The largest number of leaves a single tree may have, which controls how complex each tree is. |
| `min_samples_leaf` | The smallest number of training files a leaf may contain. Larger values prevent a tree from fitting a handful of files. |
| `l2_regularization` | A penalty on large leaf values, which makes each tree's correction more conservative. 0 means no penalty. |
| `max_features` | The share of features, chosen at random, that each split may consider. Values below 1 make the trees differ from each other. |
| `class_weight` | With `"balanced"`, errors on a rare class count for more. With `None`, every file counts the same. |

**Early stopping.** An option that stops adding trees when the score on a
held-out part of the training data stops improving. It is switched off here
(`early_stopping=False`), so that `max_iter` is exactly the number of
iterations used and every cross-validation fold trains the same model.

**Confidence.** The model outputs a probability for each class
(`predict_proba`). The confidence stored for each test file is the
probability of the predicted class. For `binary`, the probability of malware
is the score used for ROC-AUC.

**Importance measure.** `HistGradientBoostingClassifier` does not provide
MDI, so permutation importance is the only measure, as for the SVM.

## 3. The six steps and their results

### Step 1. Baseline (`src/gradient_boosting/baseline.py`)

scikit-learn's default hyperparameters (`max_iter=100`, `learning_rate=0.1`,
`max_leaf_nodes=31`, `min_samples_leaf=20`, no regularisation,
`max_features=1.0`) plus `class_weight="balanced"`, scored by 5-fold CV.

| Task | Accuracy | Macro-F1 (+/- across folds) | Dummy macro-F1 (from the Random Forest baseline) |
|---|---|---|---|
| `binary` | 0.9698 | 0.9073 (+/- 0.0066) | 0.4792 |
| `family` | 0.8242 | 0.8311 (+/- 0.0045) | 0.0608 |

For `binary`, the baseline found 92.6% of benign files but labelled 455 of
17,267 malware files (2.6%) as benign.

### Step 2. Tuning by random search (`src/gradient_boosting/tune.py`)

30 random combinations per task, each scored by 5-fold CV on macro-F1.

| Hyperparameter | Values offered |
|---|---|
| `learning_rate` | 0.02 to 0.3, drawn at random, evenly on a logarithmic scale |
| `max_iter` | 100, 200, 400, 600 |
| `max_leaf_nodes` | 15, 31, 63, 127 |
| `min_samples_leaf` | 5, 10, 20, 40 |
| `l2_regularization` | 0, 0.1, 1, 10 |
| `max_features` | 0.2, 0.5, 1.0 |
| `class_weight` | balanced, None |

| Task | Baseline | Best of 30 | Worst of 30 |
|---|---|---|---|
| `binary` | 0.9073 | 0.9337 (+/- 0.0045) | 0.8749 |
| `family` | 0.8311 | 0.8356 (+/- 0.0048) | 0.5848 |

- **`binary`:** tuning gained 2.6 points, about 6 standard deviations across
  folds.
- **`family`:** tuning gained 0.5 points, the same size as the standard
  deviation across folds. The defaults were already close to the best.
- **One combination failed badly on `family`** (0.585, with a standard
  deviation across folds of 0.058): learning rate 0.28 with small trees and
  no regularisation. The next worst scored 0.824.
- **`class_weight` made little difference**: for `binary` the best
  combination with `"balanced"` scored 0.9337 and the best without 0.9326;
  for `family`, 0.8330 and 0.8356.

### Step 3. Follow-up grid search (`src/gradient_boosting/tune_follow_up.py`)

The winning `max_features` (0.2) was the smallest value offered for both
tasks, and the winning `max_iter` for `binary` (600) was the largest. A grid
search tested values beyond those edges, with every other hyperparameter held
at the step 2 winner.

`binary` CV macro-F1:

| `max_features` \ `max_iter` | 600 | 1,000 | 1,500 |
|---|---|---|---|
| 0.1 | 0.9343 | 0.9341 | **0.9348** |
| 0.2 | 0.9337 | 0.9333 | 0.9332 |

`family` CV macro-F1:

| `max_features` \ `max_iter` | 100 | 200 |
|---|---|---|
| 0.1 | 0.8308 | 0.8350 |
| 0.2 | **0.8356** | 0.8355 |

- `binary`: the best combination gained 0.0011 over step 2, below the
  standard deviation across folds (0.003 to 0.005). All six combinations lie
  between 0.9332 and 0.9348, so the score is flat in this region. The
  highest-scoring combination was kept, for consistency with the other
  models, although `max_iter=600` scores the same within the standard
  deviation and trains 2.5 times faster.
- `family`: no improvement; the step 2 hyperparameters were kept.
- Tuning stopped here because the gains were negligible.

**Final hyperparameters** (`early_stopping=False`, `random_state=42`):

| Hyperparameter | `binary` | `family` |
|---|---|---|
| `learning_rate` | 0.1547 | 0.0355 |
| `max_iter` | 1,500 | 100 |
| `max_leaf_nodes` | 63 | 127 |
| `min_samples_leaf` | 20 | 10 |
| `l2_regularization` | 1 | 0.1 |
| `max_features` | 0.1 | 0.2 |
| `class_weight` | balanced | None |
| CV macro-F1 (+/- across folds) | 0.9348 (+/- 0.0029) | 0.8356 (+/- 0.0048) |

### Step 5. Analysis (`src/gradient_boosting/analysis.py`)

Done after the final test. It explains the finished model and changes no
hyperparameter.

**Permutation importance of single features**, measured on the test set with
5 shuffles per feature. Top five:

| `binary` | Fall in macro-F1 | `family` | Fall in macro-F1 |
|---|---|---|---|
| `hdr_MajorLinkerVersion` | 0.071 | `sec_rsrc_Misc_VirtualSize` | 0.050 |
| `hdr_DllCharacteristics` | 0.033 | `hdr_MajorLinkerVersion` | 0.038 |
| `sec_rsrc_Misc_VirtualSize` | 0.029 | `hdr_SizeOfInitializedData` | 0.030 |
| `hdr_CheckSum` | 0.021 | `hdr_AddressOfEntryPoint` | 0.028 |
| `hdr_Characteristics` | 0.014 | `dll_user32.dll` | 0.025 |

Only 13 of 299 features have an importance above 0.001 for `binary`, and 39
for `family`. All 13 `binary` features are header or section fields.

**Permutation importance of whole feature groups.** All the features of one
group are shuffled together and the fall in test macro-F1 is measured (5
shuffles).

| Group | Features | `binary` fall (from 0.939) | `family` fall (from 0.838) |
|---|---|---|---|
| PE header | 30 | 0.329 | 0.376 |
| PE sections | 38 | 0.078 | 0.216 |
| API calls | 222 | 0.026 | 0.066 |
| Imported DLLs | 9 | 0.002 | 0.049 |

**Ablation.** The model is retrained with some features removed, using the
final hyperparameters and 5-fold CV on the training set. The hyperparameters
are not re-tuned for each variant. "Top N" means the N features with the
highest permutation importance for that task.

| Variant | Features kept | `binary` macro-F1 | `family` macro-F1 |
|---|---|---|---|
| All 299 features | 299 | 0.9348 | 0.8356 |
| Without top 10 (permutation) | 289 | 0.8356 | 0.7974 |
| Without top 20 (permutation) | 279 | 0.8312 | 0.7570 |
| Without top 50 (permutation) | 249 | 0.8303 | 0.5986 |
| Header + sections only | 68 | 0.9317 | 0.8211 |
| API calls + DLLs only | 231 | 0.4779 | 0.6316 |

For `binary`, the effect on each class (recall):

| Variant | Benign recall | Malware recall |
|---|---|---|
| All 299 features | 0.861 | 0.992 |
| Without top 10 (permutation) | 0.775 | 0.962 |
| Without top 20 (permutation) | 0.789 | 0.958 |
| Without top 50 (permutation) | 0.789 | 0.957 |
| Header + sections only | 0.856 | 0.991 |
| API calls + DLLs only | 0.961 | 0.533 |

For `binary`, removing the top 20 or top 50 changes little beyond removing

importance; the ranking below those is not meaningful.

## 5. Points for the Discussion section

- **Gradient Boosting has the highest test macro-F1 on both tasks.** For
  `binary` its lead over the Random Forest is 1.2 points. For `family` it is
  0.6 points, about the size of the standard deviation across folds, so the
  two tree models are close to level on malware type.
- **Test scores match the CV estimates** (0.9390 against 0.9348; 0.8381
  against 0.8356).
- **Its `binary` gain over the forest comes from benign files.** It wrongly
  flags 34 benign files where the forest flags 48, and misses the same number
  of malware files (52 and 53). Benign recall is 0.909, the highest of the
  three models.
- **The SVM still misses the fewest malware files** (10), at the cost of 116
  false alarms.
- **ROC-AUC does not follow the macro-F1 ranking.** The forest's is slightly
  higher (0.9930 against 0.9917), although Gradient Boosting has the higher
  macro-F1.
- **The same three types are confused by all three models.** Here 200
  SnakeKeyLogger files are labelled Spyware and 124 Spyware files are
  labelled SnakeKeyLogger. That every model fails on the same pairs suggests
  the limit is in the features, not in the choice of model.
- **Downloader and RedLineStealer are easy for all three models** (F1 0.97
  and 0.95 here).
- **The linker version is this model's most important `binary` feature**
  (permutation importance 0.071; the next is 0.033) and its second most
  important for `family` (0.038). The team kept `hdr_MajorLinkerVersion` and
  this is to be disclosed (see `RANDOM_FOREST.md`, section 5). Gradient
  Boosting depends on it about as much as the forest (0.074) and more than
  the SVM (0.032).
- **`binary` detection rests on very few features.** Only 13 of 299 have a
  measurable permutation importance, all of them header or section fields,
  and removing the top 10 costs 10 points of macro-F1 (0.935 to 0.836).
- **API calls and DLLs add almost nothing to detection for this model.**
  Header and section fields alone score 0.9317, against 0.9348 for all 299.
  API calls and DLLs alone score 0.478, the level of the dummy model (0.479),
  with 47% of malware labelled benign. This is the same result as for the
  Random Forest. The SVM reached 0.771 from the same features.
- **API calls and DLLs do help with malware type**: removing them costs 1.4
  points (0.8356 to 0.8211), and alone they score 0.632. Three DLL flags
  (`user32.dll`, `kernel32.dll`, `gdi32.dll`) are among the 15 most important
  `family` features.
- **Tuning mattered for `binary` (2.7 points over steps 2 and 3) and not for
  `family` (0.5 points).** A poor combination can fail badly: one scored
  0.585 on `family`.
- **The `binary` score is flat around the chosen hyperparameters** (0.9332 to
  0.9348 across the follow-up grid), so the result does not depend on a
  finely balanced setting.
- **To state in the report:** permutation importance was measured on the test
  set, and its ranking was used to choose which features to remove in the
  ablation. This is descriptive analysis after the final test; no
  hyperparameter or model was chosen from it.

## 6. File reference

### Scripts, run in this order from the project root

| Script | Does | Time on a 24-core machine |
|---|---|---|
| `src/gradient_boosting/baseline.py` | Step 1, baseline CV | about 75 s (measured while another job was using the processor) |
| `src/gradient_boosting/tune.py` | Step 2, random search. Chooses how many models to train at once from the free RAM. | about 56 min (11 min `binary`, 45 min `family`) |
| `src/gradient_boosting/tune_follow_up.py` | Step 3, follow-up grid search. Updates `tuned_params.json` if a combination is better. | about 14 min |
| `src/gradient_boosting/final.py` | Step 4, final training and test | about 95 s |
| `src/gradient_boosting/analysis.py` | Step 5, permutation importance and ablation | about 19 min |
| `src/gradient_boosting/figures.py` | Step 6, the five figures | a few seconds |

```
python src/gradient_boosting/baseline.py
python src/gradient_boosting/tune.py
python src/gradient_boosting/tune_follow_up.py
python src/gradient_boosting/final.py
python src/gradient_boosting/analysis.py
python src/gradient_boosting/figures.py
```

Everything uses seed 42. The shared files `src/data.py`, `src/evaluation.py`
and `src/plot_style.py` are described in `RANDOM_FOREST.md`.

### Models (`models/gradient_boosting/`)

| File | Contents |
|---|---|
| `binary.joblib` | Trained benign-vs-malware model (4.5 MB) |
| `family.joblib` | Trained malware-type model (3.5 MB) |

Load and use (needs scikit-learn 1.7.0, as pinned in `requirements.txt`):

```python
import joblib, sys
sys.path.append("src")
from data import load_data

model = joblib.load("models/gradient_boosting/binary.joblib")
_, X_test, _, y_test = load_data("binary")
print(model.predict(X_test.iloc[:5]))         # 0 = Benign, 1 = Malware
print(model.predict_proba(X_test.iloc[:5]))   # probability of each class
```

The `family` model predicts the type numbers 1 to 6; `TYPE_NAMES` in
`src/data.py` maps them to names.
